# Jason Hise / Entropy Games notes

Research pass: 2026-10-06.

## Credit statement

Spinor should be understood as part of the visual and pedagogical lineage of Jason Hise's spin-½, belt-trick, antitwister, and higher-dimensional geometry work. In particular, the use of a central object with multiple attached ribbons/fibers to make the distinction between 2π and 4π visible owes a clear debt to Hise's animations. The goal of this repository is to make that visual idea directly manipulable on modern hardware while keeping the mathematics and provenance inspectable.

Nothing in this repository should imply that we originated Hise's visual construction, or that our independently written implementation is Hise's original code. When Spinor is shown publicly, Hise should be credited by name and linked to his own work.

Jason Hise is the person behind the belt-trick / antitwister / 4D animations we had discussed earlier.

## Original Wikipedia-era workflow

Primary source:

- Jason Hise, “Why I create beautiful math GIFs”, Wikimedia Diff (2016):
  https://diff.wikimedia.org/2016/09/22/math-gifs/
- Wikimedia user pages:
  https://commons.wikimedia.org/wiki/User:JasonHise
  https://en.wikipedia.org/wiki/User:JasonHise
- Entropy Games:
  https://entropygames.net/
- YouTube channel:
  https://www.youtube.com/channel/UCw5aOpkU7_uuL73-kVxdJIA

Hise says his usual production pipeline was:

1. write a C++ Maya plugin containing a custom shape node;
2. create that procedural shape inside Maya;
3. give it an ordinary Maya material;
4. animate/tune the node parameters;
5. let Maya render the frame sequence;
6. assemble the frames into a movie or GIF.

For 4D geometry he says the custom node imports a 4D mesh from a text file, performs rotations in 4D, then projects the result into 3D. This is important architecturally: the nonstandard mathematics lived in the procedural shape; the renderer did not need to “understand 4D”.

For the spin-½ / belt-trick material, Hise says the first animation was manually keyframed and a later one was generated by code. He then extended the construction to arbitrarily many fibers to show a whole continuous region of space twisting without tangling.

A commenter explicitly asked Hise to put the visualization code on GitHub. I did not find a public repository containing the original Maya custom node or the old belt-trick generator. Do not silently substitute a reconstruction for Hise's original source.

The old animated assets themselves are explicitly marked public domain / CC0 in the Wikimedia article. That does **not** imply that every source-code artifact on Entropy Games is CC0.

## Older C++ math-library trail

In March 2006 Hise posted to the Boost developers list about a geometry/math library written for his game engine:

- https://listarchives.boost.org/Archives/boost/2006/03/102357.php
- follow-up: https://listarchives.boost.org/Archives/boost/2006/03/102370.php

He describes generic:

- `vector<Type, Dim>`
- `matrix<Type, Rows, Columns>`
- quaternion
- common operations on those types
- generic sine/cosine work needed by the quaternion implementation

He also offered relevant parts of his software rasterizer, including transformation/projection matrix and color routines.

The archive was called `geometry_math.zip` and was uploaded to the old Boost Vault / Math-Geometry area. I did not recover a surviving copy in this pass. Keep this as a source-recovery lead, not as code we already possess.

## Tesseract / 4D trail

Hise's older tesseract and polytope animations were produced with Maya; some public descriptions also mention Macromedia Fireworks for final GIF assembly.

Earlier research in this project family also identified an old Hise “Tesseract Explorer” program, apparently separate from the Maya-rendered GIF workflow. I have not recovered its original source or a trustworthy surviving download in this pass, so it should remain marked as an unresolved provenance lead.

The useful confirmed implementation idea is simpler and stronger anyway:

```
4D mesh / procedural data
    -> 4D transformations
    -> 4D -> 3D projection
    -> ordinary 3D geometry
    -> ordinary renderer
```

That decomposition maps cleanly to our own render backends.

## Hise's newer browser work

Hise is active again on interactive browser visualizations. His Mathstodon account is:

https://mathstodon.xyz/@jasonhise

He has recently described the goal as making advanced geometry tangible enough for a child to poke at on an iPad.

### Twist Gallery

https://entropygames.net/twist_gallery.html

The indexed page identifies itself as:

- “Twist Gallery”
- “antitwister scaffolds”
- “onion-slerp”

Exposed controls include twist, core spin speed, strand count, tube radius, belt width/thickness, inner radius, shell resolution, twist decay, lattice extent, and multiple shading/film controls.

This is a particularly relevant modern descendant of the old Hise animations. It should be studied before inventing our deformation field from scratch.

### 4D Polytope / Hypershape Gallery

https://entropygames.net/hypershape_gallery.html

The indexed page exposes a browser 4D polytope viewer with:

- 4D field of view
- perspective/soap-film style projection
- face and edge controls
- autorotation
- iridescent/classic shading

Hise has described this as an interactive 4D gallery and notes that its URL stores selected scene/rendering settings.

### 600-cell drag UI

https://entropygames.net/files/shared/600_cell_six_sheets.html

Indexed title:

> 600-cell · six toroidal wire grids · clean drag UI

Controls include sheet selection, stereographic projection, connectors, tetrahedra, and coloring.

This is direct evidence that Hise's current visualization work already treats drag interaction as a first-class input. Our proposed spinor toy should therefore be compared with his current browser interaction, not only with the old GIFs.

## What we can safely reuse

### Directly reusable or reference-safe

- mathematical ideas and algorithms, independently implemented;
- CC0/public-domain Wikimedia animation assets where useful;
- external code whose license is explicitly compatible and retained.

### Do not copy until license is explicit

- source from current Entropy Games browser pages;
- any recovered old Hise Maya/C++ source;
- any historical binaries/source dump without provenance.

The Entropy Games front page says the Wikipedia GIFs are public-domain and gives separate reuse terms for videos. That is not a blanket source-code license.

## Design implications for this repository

The interesting step is not “make another 720° animation”. It is to make the construction **manipulable**.

A first version should let a person:

- grab the central body and rotate it directly;
- watch all attached ribbons update continuously;
- stop anywhere, reverse direction, and inspect the stored twist;
- feel the difference between 2π and 4π as state, not as narration;
- use touch as naturally as mouse/pointer input.

Hise's work supplies both the visual lineage and several possible deformation constructions. We should keep the input/state/render split explicit so later experiments can replace a canonical ribbon field with richer surfaces or different attachment graphs without replacing the whole program.
